GISAAH STORE — FRONT-END (WEB) UX AUDIT NOTES
=================================================
Generated from senior UX audit (Web codebase review)
Stack: React/Vite, React Router, SWR, Tailwind, Framer Motion, SiteConfigContext

================================================================================
WHAT IS ALREADY SOLID (KEEP)
================================================================================

- Conversion-oriented homepage: category belt, carousels, config-driven sections
- Lazy routes + SWR prefetch + skeletons on main paths
- RTL Arabic-first layout
- Product detail: gallery, variants, sticky mobile buy bar, SEO/JSON-LD
- Site customization wired for branding, theme CSS vars, homepage, WhatsApp FAB
- WhatsApp checkout fits local market behavior

================================================================================
1. APP ROUTING (App.jsx)
================================================================================

Routes
------
/               HomePage (eager load)
/products       ProductsPage
/categories     CategoriesPage
/category/:slug CategoryPage
/brand/:slug    BrandPage
/product/:slug  ProductDetailsPage
/about, /contact, /branches, /privacy-policy
/auth           AuthPage
/cart           CartPage
/favorites      FavoritesPage
/profile        ProtectedRoute
/my-orders      ProtectedRoute (Buyer, Admin)
/admin          ProtectedRoute (Admin)
/product-grid-demo  ProductGridDemo (public — likely unintended in prod)
*               Redirect to / (no 404 page)

Strengths
---------
- Code splitting: only HomePage eager; others lazy-loaded with Suspense
- RouteErrorBoundary + AdminDashboard chunk fallback
- SEO-friendly product URLs (/product/:slug)
- SWR preload for categories, site config, first product page
- ScrollToTop, WhatsAppFAB, BackToTop outside route tree

Problems
--------
- Catch-all redirect hides 404s — bad URLs give no guidance
- /product-grid-demo is publicly accessible — likely unintended in production
- Protected routes send to /auth with no returnUrl
- Post-login always navigate("/") — not back to cart/profile/orders
- ChatWidget commented out — only WhatsApp for support

================================================================================
2. LAYOUT & NAVIGATION (Layout.jsx, MobileBottomNav.jsx)
================================================================================

Architecture
------------
- RTL (dir="rtl"), sticky header, desktop nav, mobile hamburger
- Persistent mobile search bar, Footer, MobileBottomNav, BannerRenderer
- Brand intro: ~1.3s logo animation on first session (sessionStorage: gisaah_intro_seen)

Strengths
---------
- Dense conversion header: search, favorites badge, cart badge, auth/profile, admin
- Responsive search: full bar (xl+), toggle drawer (md–xl), sticky mobile search
- Mobile bottom nav: 4 tabs — Home, Categories, Cart, Account
- Desktop nav has aria-label and active-state styling
- Rich mobile menu: categories, offers, orders, favorites, about, contact, branches
- Safe-area padding on bottom nav

Problems
--------
P1 — First-visit logo intro blocks interaction (~1.3s)
  - Full-screen overlay z-[9998], header hidden until intro finishes
  - No prefers-reduced-motion bypass
  - Hurts LCP and time-to-interaction on first visit

P2 — headerOverHero computed but never used — transparent header-over-hero unfinished

P2 — Dark mode toggle fully hidden (className="hidden" on theme button)
  - Users cannot switch theme from UI despite dark mode support existing

P2 — Mobile menu accessibility gaps
  - No backdrop, focus trap, Escape-to-close
  - Hamburger missing aria-expanded
  - Accidental-tap and keyboard/screen reader risk

P1 — Duplicate search UX
  - Layout search navigates to /products?search=…
  - ProductsPage has its own search — not bidirectionally synced
  - Layout search not initialized from URL when landing on /products?search=…

P2 — Nested <main> landmarks
  - Layout wraps children in <main>
  - HomePage and ProductsPage add another <main> inside — invalid HTML

P1 — Favorites not in bottom nav (header + hamburger only)

P3 — Cart link in header lacks aria-label on small screens (icon-only)

P1 — Three fixed layers on mobile PDP/cart
  - MobileBottomNav (z-50, h-14)
  - ProductDetailsPage sticky bar (z-40)
  - WhatsAppFAB (z-40, bottom-24)
  - Crowded lower third on small viewports

3. CHECKOUT & CART (CartPage.jsx) — P0 TRUST ISSUE
================================================================================

Current flow
------------
Cart → "إتمام الطلب" expands inline form (address + COD)
     → WhatsApp handoff (backend createOrder is COMMENTED OUT)
     → Success screen + cart cleared

Strengths
---------
- Empty cart state with CTA
- Line-item qty controls, stock cap warning, clear-cart confirm
- Trust copy before confirm, loading state on submit

Critical problems (P0)
----------------------
1. Success screen says "تم إنشاء الطلب بنجاح!" but NO order is created in DB
2. CTA "متابعة طلباتي" → /my-orders will likely be EMPTY for WhatsApp-only orders
3. UI suggests formal order creation; implementation is WhatsApp redirect only

High problems (P1)
------------------
- Only address field — no name/phone; merchant infers customer from WhatsApp
- "التوصيل: مجاناً" hardcoded — not from site config
- Auth not required (commented out) — fine for WhatsApp, inconsistent with MyOrdersPage
- Cart total assumes single currency (items[0].currency)
- No "continue as guest" messaging aligned with auth flow

4. SEARCH (ProductsPage.jsx, Layout.jsx, CategoryPage.jsx)
================================================================================

Behavior by location
--------------------
Layout.jsx      → Submits to /products?search=query
ProductsPage    → Local searchText + 500ms debounce; reads URL on mount only
CategoryPage    → Local search within category
CategoriesPage  → Filters category names client-side

Critical problems (P0)
----------------------
- ProductsPage typing does NOT update URL — breaks share/bookmark/back button
- Sort (sortOrder) reads URL once but changes don't write back to searchParams
- Layout search state not initialized from URL on /products?search=…
